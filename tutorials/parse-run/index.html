Parse, modify and reload a ReEDS fixture

Turn the repository’s Pacific test run into a saved, inspectable system. You will read ReEDS data, inspect an hourly demand profile, split aggregated generators into reference-sized units, and reload the result with Infrasys-compatible APIs. No licensed target-model software or external ReEDS run is needed for this fixture.

The ReEDS model produces the capacity-expansion runs consumed here. r2x-reeds parses those results and applies optional system modifiers; it does not solve the ReEDS model.

What you will build

Section titled “What you will build”
flowchart TD
  A["Pacific fixture copy<br/>2032 capacity, 2012 weather"] --> B["ReEDSParser<br/>regions, generators, demand"]
  B --> C["Inspect hourly demand"]
  C --> D["break_generators<br/>reference-sized units"]
  D --> E["Infrasys JSON<br/>and time-series directory"]
  E --> F["Reload and compare counts"]

The saved artifact contains ReEDS components, not a PLEXOS or Sienna export. Target conversion is a later step performed by R2X translation plugins.

Before you start

Section titled “Before you start”

Complete installation, environment setup and verification. Keep that environment active and work in your empty reeds-example directory. This tutorial uses the public r2x-reeds 0.9.3 and r2x-core 0.9 APIs. No source checkout is required.

Inspect from the CLI or continue to a target

Section titled “Inspect from the CLI or continue to a target”

The saved-system guide shows r2x read and repeatable inspection scripts. It uses the CLI’s own environment; the source checkout’s uv environment is separate.

For a native target export, continue with ReEDS to PLEXOS or ReEDS to Sienna. Those workflows add a translator and target exporter after the parser; the serialized ReEDS JSON above is not either target’s native format.

The documentation tests execute these console assertions against the current source and its locked dependencies. The count/profile/reload checks apply to this fixture revision and selected years. Published package versions can differ from current source, especially in optional input upgrades and operating-cost fields.
